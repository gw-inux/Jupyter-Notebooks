**Use this Mehl (2006) case in section 2** transfers the selected theory case and restores its published starts, default closure and unzoomed views. **Reset** returns to the currently entered starts. Enable **Run to closure**, then press a play button to complete a path. With **Sync** on, either active play button runs both available methods. With it off, each button runs only its own method. Switching the toggles alone never advances the iteration. Completed paths with default starts/closure match section 1. Changing the starts changes the paths, but not the physical model or its function curves.

**Editable experiments.** Start confined without ET, then switch to unconfined flow, and finally add ET. These three presets use $K_L=K_C=K_R=10^{-4}$ m/s, $h_L=7$ m, $h_R=2$ m and initial central head 4 m. Initial-head inputs change in 0.1 m increments; boundary heads change in 0.5 m increments. Cell-centre spacing is 100 m and width is 1 m. Recharge is zero, as in Mehl's three-node balance (equation 1).

**Physical geometry.** The confined layer is 5 m thick, from −5 to 0 m; both specified heads lie above its roof. The unconfined aquifer extends from 0 to 8 m. Its saturated thickness is $b(h)=\min(h,8)-0$ for $h>0$, so transmissivity becomes constant if the head reaches the aquifer top. These are separate conceptual geometries, not a transient conversion of one aquifer into another. The cell frames mark the actual bottom and aquifer top. Horizontal head marks in the central cell show the current Picard and Newton estimates. The heavier line and larger marker identify the method that just advanced. A synchronized step can emphasize both methods. The darker dashed line marks the reference head. Specified-head cells have one fixed head line and a numeric head label, with no Picard/Newton markers because these boundary values do not change. Cell names appear near the top of the sketch. The italic number row identifies the cells in the interactive cross-section.

**True head** means an independently verified solution of these **discrete equations**, not exact knowledge of a real aquifer or an analytical continuum solution. It is available before the first learner update. The profile fills the cells to the reference head and overlays the current Picard/Newton heads as lines and symbols. The status initially reads *Initial guess*.

The ET preset uses surface elevation 7.5 m, extinction depth 4 m (extinction elevation 3.5 m) and maximum rate 1000 mm/year. ET inputs appear only while enabled and are remembered when hidden. The discharge is continuous, but its slope changes between branches and the Picard map can jump. At a breakpoint, the code takes the adjacent constant-branch derivative. No damping is used in this first experiment.

Picard and Newton use the same balance. The single control row above their plots contains **▶ Picard**, **▶ Newton**, **Sync**, **Run to closure** and **Reset**. With Run to closure off, a play button attempts one update; with it on, it continues to convergence or a diagnosed stopping condition. Sync is initially off. Turning it on puts both buttons inside a common frame and applies that action to both available methods. A converged button becomes **✓ Picard** or **✓ Newton** and is disabled, while the other method can continue. A stopped method uses a square instead of a convergence check mark. Both closure criteria must be satisfied. A linear model can reach the head solution in one update, but needs another update to verify a small head change. Changing closure criteria reassesses the saved iterate; it does not reset the history. The zoom toggle sits immediately below each plot and changes only the view; the current head and compact status checks follow it.

**Reading convergence.** Defaults are 1E-4 m for head change and 1E-6 m³/s for flow residual. Both checks must pass; another update may be required when flow closure passes but head-change closure does not. The convergence figure shows flow residuals and head changes on separate logarithmic axes, each fixed from 1E-12 to 100. Axis and closure colors match: purple for flow, ochre for head change. Edge triangles identify values outside the window; the stored numerical values remain unchanged.
